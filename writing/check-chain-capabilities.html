Check what a chain exposes before you trust an XCM route

Tyler Woods · 2026

A chain can accept a WebSocket connection, answer a balance query, and still have no way to build the transfer you asked for. The failure surfaces as a thrown error at build time, after the amount and the recipient are set, and the message usually names a method rather than the missing capability.

Four runtime checks decide whether a route can be built, fee-estimated, and dry run. They take one command to print.

1. The baseline transfer method

The SDK needs the chain's XCM pallet, PolkadotXcm or XcmPallet, and the transfer_assets extrinsic. Without either, the ordinary asset-transfer path has nothing to call.

2. transfer_assets_using_type_and_then

Some routes cannot use the baseline call. A relay asset on an origin that does not reserve it needs type-and-then to place the fee and the transferred asset in one message. Some external-asset routes cross the same branch. When the method is missing, the SDK throws TypeAndThenUnavailableError for those routes instead of building an invalid call. That is the correct failure. It is still a route that will not work.

3. DryRunApi

Dry run is how the SDK turns a built call into a fee and a success check. Without it, fee estimation falls back to other sources, and the type-and-then path loses the pass that would have replaced its fee placeholder. On chains that also lack the payment API, a transfer can be built with a fee it cannot verify. The public report on the placeholder path is xcm-tools#2353.

4. XcmPaymentApi

This is the fee-query interface the SDK prefers when it exists. Without it, the SDK uses paymentInfo or dry run instead, and some execution paths check the flag before trusting a fee from this source.

Run it

The script is check-chain-capabilities.mjs. It uses @paraspell/sdk from npm and connects to each chain's default endpoint.

npm install @paraspell/sdk
node check-chain-capabilities.mjs Centrifuge Pendulum Peaq Heima

Example output

Run against four Polkadot parachains on 29 October 2026:

chain             pallet        typeThen  transferAssets  DryRunApi  XcmPaymentApi  native
Centrifuge        PolkadotXcm   no        yes             no         no             CFG (18 decimals)
Pendulum          PolkadotXcm   no        yes             no         no             PEN (12 decimals)
Peaq              PolkadotXcm   yes       yes             no         no             PEAQ (18 decimals)
Heima             PolkadotXcm   yes       yes             no         no             HEI (18 decimals)

How to read it

  • typeThen no, transferAssets yes. Ordinary transfers can be built. Relay-asset routes from that chain stop at TypeAndThenUnavailableError unless the chain reserves the asset and the SDK takes the reserve path.
  • typeThen yes, DryRunApi no. The type-and-then branch can build, but it cannot dry run for fees. This is the combination behind the placeholder report above.
  • XcmPaymentApi no. Fee figures come from another source. Check which one for the path you care about before trusting a quote.
  • Every column yes. The chain exposes the surface. It does not mean a given asset has a working route.

What it does not check

Asset listings, decimals, existential deposits, the destination's support for the asset, the reserve chain, XCM version negotiation, and whether a route exists at all. Those come from the asset map and the destination, not from the origin's metadata. A green table is a necessary condition, not a route test.
